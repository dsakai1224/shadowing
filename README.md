# Shadowing Studio

英文を入力すると Gemini TTS で読み上げ、発音・イントネーション・意味の区切りを確認するための
シャドーイング練習ツール。GitHub Pages に置いて、iPad のホーム画面から起動できます。

---

## 構成

```
index.html              アプリ本体（依存ライブラリなし・CDN も使わない）
manifest.webmanifest    PWA マニフェスト
sw.js                   Service Worker（ホーム画面起動・オフライン起動用）
icon-192.png            アイコン
icon-512.png            アイコン
apple-touch-icon.png    iOS ホーム画面用アイコン
README.md               これ
```

## 1. リポジトリを作って公開する

1. https://github.com/new → Repository name を入力 → **Public** → Create repository
   （「Add a README file」はチェックしない）
2. 空リポジトリ画面の **「uploading an existing file」** から、上記ファイルを全部ドラッグ&ドロップ → Commit changes
3. **Settings → Pages** → Source: `Deploy from a branch` / Branch: `main` `/ (root)` → Save

1〜2分で `https://<ユーザー名>.github.io/<リポジトリ名>/` が開きます。

## 2. API キーを入れる

1. https://aistudio.google.com/apikey で「Create API key」
2. 公開したページ下部の **設定** パネルを開き、キーを貼って「保存」

キーは**その端末のブラウザ**（`localStorage`）にだけ保存されます。
リポジトリにもサーバーにも送られず、通信先は `generativelanguage.googleapis.com` だけです。
**iPad と PC の両方で使うなら、それぞれで一度入力が必要**です。

## 3. iPad のホーム画面に追加する

Safari で開く → 共有ボタン → **「ホーム画面に追加」**

これで Safari の UI が消えたフルスクリーンのアプリとして起動します。
起動だけはオフラインでも可能ですが、音声生成には通信が必要です。

## 使い方

1. 英文を貼る → **「文に分割して読み込む」**
2. 各文の下に**日本語訳と、設定レベルで必要な語句の解説**が出る
3. 各文の **▶ 再生**
4. **比較** ＝ 同じ文を「ゆっくり明瞭」と「自然な会話速度」で交互に2往復再生

4 が本命の機能です。この2つの差分こそがリンキング・音の脱落・弱形といった、
テキストを読んでいるだけでは気づけない部分です。

## 訳と語句の解説

分割した各文の下に、日本語訳と語句解説が付きます。

- **訳**：直訳ではなく、原文のレジスター（丁寧さ・かたさ）を保った自然な日本語
- **語句**：設定した TOEIC レベルで「知らない可能性が高い」「文脈上の意味が非自明」な語句のみ
  - 単語ごとの意味ではなく **この文脈での意味**
  - **句動詞・イディオム・コロケーションを優先**して拾います。`follow up on` や `on your end` のように、
    個々の単語は易しいのに意味が非合成的なものこそ、実際の会話で詰まる原因だからです
  - 品詞・IPA 発音記号・使用場面の注記つき
  - 🔊 ボタンでその語句だけを単体で発音させられます
- レベルは 500 / 600 / 700 / 800 / 900 から選択（初期値 700）。変えると解説の粒度が変わります

### 仕組みとコスト

TTS とは別のテキストモデルに、**全文をまとめて1リクエスト**で構造化出力（`responseSchema`）を
要求しています。文ごとに呼ばないので、10文でも API 呼び出しは1回です。
テキスト生成は音声より桁違いに安く、無料枠も TTS より緩いため、実質的な追加コストはほぼありません。

取得した訳・語句は端末に保存され、同じ英文・同じレベルなら再取得しません
（アプリを閉じて開き直しても復元されます）。
「分割時に訳と語句を自動取得する」のチェックを外せば、手動で「訳・語句を取得」を押したときだけ実行されます。

### 読み上げスタイル

Gemini TTS は「どう読むか」を自然言語で指示できます。プリセット6種類＋カスタム記述。
カスタムは英語で書くほうが確実に効きます。

```
Read the following slowly, stressing every content word and pausing at each comma:
```

### 再生コントロール

| 項目 | 内容 |
|---|---|
| 再生速度 | 0.5〜1.3×。ピッチを保ったまま変速するので音質が崩れません |
| 繰り返し回数 | 1〜8回 |
| 繰り返しの間隔 | 0〜3秒（自分が発話する間） |

再生中は Wake Lock で画面がスリープしません。

### キーボード（Magic Keyboard 等）

| キー | 動作 |
|---|---|
| `Space` | 現在の文を再生 |
| `J` / `K` | 次の文 / 前の文 |
| `Esc` | 停止 |

### その他

- 一度生成した音声はタブ内にキャッシュされ、聴き直しは API を消費しません
- 各文の `⤓` で WAV ダウンロード（24kHz / 16bit / モノラル）
- 音声は30種類。学習用途では **Iapetus / Erinome（明瞭系）** から試すのが無難
- 英文・速度・スタイルなどの設定は端末に保存され、次回起動時に復元されます

## 料金と無料枠

### Google AI Pro を契約していても API は無料になりません

Google AI Pro / Ultra の特典は **AI Studio の Web 画面の中でのみ有効**です。
API キーを使った外部アプリ（＝このツール）からの呼び出しは、公式ドキュメントの表現で
「別途課金・別途管理」となります。サブスクとは完全に別会計です。

### 課金されない確実な方法

**モデル選択ではなく、Google Cloud 側で Cloud Billing を有効化しないことです。**
請求先が紐づいていないプロジェクトのキーは、無料枠のないモデルを呼んでも課金されず、
代わりに 403 や 429 のエラーが返ります。どのモデルを選んでも請求は発生しません。

一方で無料枠には代償があります。**入出力が Google の製品改善に利用されます。**
業務上の非公開情報（契約書の文面、社内メールの本文など）は貼らないでください。
一般的な英語教材や自分で書いた練習文なら問題ありません。

### どのモデルが使えるかは、本番の呼び出しから学習する

無料枠の対象モデルや、混雑しているモデルは頻繁に変わるため、このツールは
**「どれが使えるか」のリストを持ちません**。代わりに、**実際の訳・語句取得や
読み上げのリクエストの結果を記録**して、次回の試行順序に反映します。
確認のための追加リクエストは **0本** です。

記録はモデルごとに、成功時刻・失敗時刻・失敗の種類（恒久／一時的）。
ドロップダウンには結果が印として出ます（項目を長押し／ホバーで詳細）。

| 印 | 意味 |
|---|---|
| `✓` | 直近の呼び出しで成功している |
| `△` | アクセス権はあるが、直近で混雑・レート上限だった |
| `✗` | 提供終了、または無料枠の対象外 |
| （印なし） | まだ使ったことがない |

この記録は2つの形で効きます。

1. **試行順序** — 選択中のモデルを必ず最初に試したうえで、以降は実績のあるモデルを優先します。
   「新しい＝信頼できる」ではないため（実際 `gemini-3.7-flash` は最新世代で最も不安定でした）、
   世代の新しさよりも実績を先に見ます。
2. **無駄なリトライの省略** — 直近15分以内に落ちたと分かっているモデルは、
   待って粘らずすぐ次へ回します。

実測してみると、同じ状況でのリクエスト本数は 8本 → 2本 に減りました。

### 手動で全部確かめたいとき

設定の **「どれが使えるか実測」** は、上位5件のテキストモデルに数トークンの
最小リクエストを送って即座に判定する手動ツールです。金額は8モデル分で
約0.008円と無視できますが、**リクエスト本数は実作業（1本）より多く消費する**ため、
毎回押す使い方は想定していません。何かが壊れたときの切り分け用です。

なお 429／503 は「アクセス権はあるが今は詰まっている」状態なので、
使えない（`✗`）ではなく `△` として扱います。

### モデル選択とフォールバックの関係

**あなたが選んだモデルが常に最優先で使われます。** ただし、それが使えなかったときの
挙動が「無料枠で使えないモデルだった場合、自動で別のモデルに切り替える」
チェックボックス（初期値 ON）で変わります。

| チェック | 選択モデルが使えないとき |
|---|---|
| ON | 一覧の上から順に最大4件試し、通ったモデルで処理を完了させる |
| OFF | エラーを表示して止まる。モデルは一切変更しない |

エラーの種類ごとに、対処と記憶の仕方を分けています。

| エラー | 意味 | 対処 | 選択の記憶 |
|---|---|---|---|
| **503 / 500 / 504** | モデル側の一時的な混雑 | **同じモデルで** 1.5秒→4秒と待って再試行（モデルを変えても意味がないため）。それでも駄目なら別モデル | 元に戻す |
| **429** | レート上限超過 | すぐ別モデルへ（待っても回復しないことが多い） | 元に戻す |
| **403 / 404** | 無料枠対象外・提供終了 | 別モデルへ | **変更して記憶** |

一時的なエラーで選択を書き換えないのが要点です。混雑が解消すれば、また元の（通常は新しい）モデルに戻ります。
どの経路を通ったかは下部のステータスに表示されます。

### TTS の無料枠

TTS 側は無料枠のリクエスト上限が極端に少なく（`limit: 3` という報告があります）、
実測ボタンを押すだけでその枠を使い切ってしまうため、**実測の対象はテキストモデルのみ**にしています。
TTS が 429 で止まる場合は、少し待つか Cloud Billing の有効化を検討してください。
現実的な練習量（毎日10文ずつ、比較機能つき）なら月200〜300円程度です。

自分のアカウントの実際の上限は
https://aistudio.google.com/rate-limit で確認できます。

### 有料時の目安

Gemini の音声は **25 トークン/秒** で課金されます。

課金の単位は **生成された音声の長さ** です。入力したテキストの量でも、
練習に費やした時間でもありません。**一度生成した音声の聴き直しは無料**なので、
実際の練習時間は生成音声の長さよりずっと長くなります。

| モデル | 音声出力単価 | 90秒 | 1日2.5分×30日 | 1日10分×30日 |
|---|---|---|---|---|
| `gemini-3.1-flash-tts-preview` | $20 / 1M tokens | $0.045 | 約 $2.25／月 | 約 $9.00／月 |
| `gemini-2.5-flash-preview-tts` | $10 / 1M tokens | $0.023 | 約 $1.12／月 | 約 $4.50／月 |

### 「1日◯分」の目安

読み上げ速度を 140 wpm とすると、生成音声の長さはおおよそこうなります。

| 生成音声 | 分量 | 比較機能（2版生成）を使う場合 |
|---|---|---|
| 2.5分 | 約 350 語 ≒ 25 文 | 約 12 文 |
| 10分 | 約 1,400 語 ≒ 100 文 | 約 50 文 |

現実的な1セッション（10文×15語）を試算すると、

- 再生のみ：約 64 秒 → **1回 約5円**（毎日30日で $0.96）
- 比較を使う：約 129 秒 → **1回 約10円**（毎日30日で $1.93）

毎日10文ずつ比較機能つきで練習しても、**月200〜300円程度**です。
1日10分ぶんの音声を生成するのは、100文（比較なら50文）を新規に読ませる量なので、
通常の練習ではそこまで到達しません。

画面下部に、そのセッションで実際に生成した秒数と概算コストが出ます。
訳・語句のテキスト生成は音声の数十分の一なので、この表には含めていません。

### モデルは2つ使います

| 用途 | 設定項目 | 既定値 |
|---|---|---|
| 読み上げ | 読み上げモデル（TTS） | `gemini-3.1-flash-tts-preview` |
| 訳・語句 | 訳・語句モデル（テキスト） | `gemini-flash-latest` |

テキスト側の既定値を **`gemini-flash-latest`** にしているのは意図的です。
Gemini のモデルは数か月単位で世代交代し、古い版は新規ユーザーに対して提供終了になります
（`gemini-2.5-flash` は既にこの状態）。`-latest` は常に現行の Flash 系を指すエイリアスなので、
放置していても壊れません。特定世代に固定したい場合だけ番号付きのモデルを選んでください。

### モデル名が変わっても壊れないようにしてある

1. **自動切替**：モデルが廃止されていると、Google は 404 の本文で後継モデル名を返します
   （`Please update your code to use models/gemini-3.8-flash`）。その名前を拾って自動で差し替え、
   1度だけ再試行します。ユーザー操作は不要です。
2. **起動時の掃除**：提供終了が判明している世代（`gemini-2.5-*` など）が端末に保存されていたら、
   起動時に既定値へ戻します。
3. **一覧の並べ替え**：「利用可能なモデルを取得」は候補が30件以上返ってくることがあるため、
   世代が新しく安定している順に並べ替え、上位を **「推奨」**、残りを「そのほか」として
   グループ分けします。用途に合わない gemma / embedding / customtools 系は除外します。

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| 音が出ない（iPad） | 本体側面の消音スイッチ／コントロールセンターのミュートを確認。iOS は HTML5 音声をミュートスイッチに従わせます |
| 「再生がブロックされました」 | iOS の自動再生制限。画面をどこか一度タップしてから再度再生してください |
| 429 エラー | 無料枠のレート上限。少し待つか Cloud Billing を有効化。**AI Pro の契約では上限は上がりません** |
| 503 エラー（high demand） | モデル側の一時的な混雑。1.5秒→4秒と待って自動で再試行し、それでも駄目なら別モデルで処理します。表示されるのは全部失敗したときだけなので、数分おいて再実行してください |
| 404 エラー | モデルが提供終了。通常は後継モデルへ自動で切り替わって再試行されます。それでも出る場合は設定の「利用可能なモデルを取得」→「推奨」から選択 |
| 更新が反映されない | Service Worker のキャッシュ。ページを再読み込みすれば新しい版が読まれます（index.html は network-first） |

## 技術メモ

**iOS/iPadOS の自動再生制限への対処**が実装上の最大のポイントです。
Safari は「ユーザー操作から直接呼ばれた `play()`」しか許可しないため、
`await` を挟んだ2回目以降の `new Audio().play()` は必ず失敗します
（＝ループ再生と通し再生が動かない）。
そこで **Audio 要素を1つだけ生成し、最初のタップで無音 WAV を再生してロックを解除**、
以降は `src` を差し替えるだけにしています。

その他：

- Gemini TTS の応答は base64 の生 PCM（`audio/L16;codec=pcm;rate=24000`）で返るため、
  ブラウザ側で 44 バイトの WAV ヘッダを付けて Blob 化しています（`pcmToWav()`）。
- 入力欄の `font-size` は 16px。これ未満だと iOS がフォーカス時に自動ズームします。
- Service Worker は index.html を network-first にしてあるので、
  push した更新が古いキャッシュで固まることはありません。
- `sw.js` は自オリジンのみ扱い、Gemini API へのリクエストには一切介入しません。
- 訳・語句は `responseMimeType: "application/json"` と `responseSchema` を指定した
  構造化出力で取得しています。自由文をパースするのではなくスキーマで型を固定しているため、
  表示側でのパース失敗が起きません。
- 初期化処理（`init()`）はスクリプト末尾で呼んでいます。`splitSentences()` が参照する
  `ABBR` が `var` 宣言のため、先頭で即時実行すると undefined を触って落ちます。
